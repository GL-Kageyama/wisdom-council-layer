# サンプル入力：OSSソフトウェア

**v1 初案**
```
■ プロジェクト名: STRAND（ストランド）—「文脈の糸」
■ 種別: オープンソースCLIツール（MITライセンス・個人の副次プロジェクト）
■ 概要: 開発作業中の「文脈」—直近の編集ファイル・テスト失敗・git状態・メモ—を自動収集し、単一の共有可能なファイル（コンテキストバンドル）にパッケージするCLI。AIアシスタントへの貼り付けや、チームメンバーへの引き継ぎにそのまま使える。
■ 対象ユーザー: 生成AIを開発に使う個人開発者・チーム
■ 提供機能: 編集履歴の自動収集／テスト失敗のスナップショット／バンドル生成（Markdown・JSON）／git状態の要約
■ 収益・持続性: オープンソース。寄付とスポンサー（GitHub Sponsors）想定。
■ 差別化: 「プロジェクトの背景を毎回説明し直す手間」をなくす。
■ 課題: 文脈詰め込みツールは多数存在し、フォーマットがバラバラで相互運用がない。バンドルは一度きりの貼り付けで消費され、価値が蓄積しない。
```
- content_type: structured / domain: digital / mode: full

**v2 改訂案（作成スキルの再作成指令を反映）**
```
■ プロジェクト名: STRAND（ストランド）— v2改訂版
■ 種別: オープンソースのコンテキスト交換規約（CSF: Context Strand Format）＋参照実装CLI
■ 概要: 「開発文脈の交換規約」という位置づけへ再定義。収集した文脈を単一のJSON（CSF）として、バージョン・署名・差分・クエリ可能な形式で保存し、CI・コードレビュー・ドキュメント生成・AIエージェントが同じストランドを読み書きできる共通基盤を提供する。
■ 差別化: 「貼り付けるためのバンドル」ではなく「ツール間で取り回す規約」を商品化する。CLIは参照実装の一つに過ぎず、価値の本体はフォーマットとそれを取り巻くエコシステム。
■ エコシステム価値: 複数ツールが同じCSFを採用することで、採用数が増えるほど相互運用性と移行コストが上がる（ネットワーク効果）。RFCプロセス・SemVer・保守ワーキンググループによるガバナンスでフォーマットの耐久性を担保。
■ 収益・持続性: オープンソースのエコシステム基盤。スポンサー・採用ツールの商用版・コンサル。フォーマットはオープンで、特定ベンダーに依存しない。
■ v1からの変更点: 「使い捨ての貼り付け」から「蓄積・交換できる資産」へ。差別化の焦点を機能（CLI）から規約（フォーマット＋エコシステム）へ移した。
```

**v3 改訂案（作成スキルの再作成指令を反映）**
```
■ プロジェクト名: STRAND（ストランド）— v3改訂版
■ 種別: オープンソースのコンテキスト交換規約（CSF）＋バリデータ/参照実装＋初期エコシステム
■ 概要: v2の規約（CSF）を採用の実証へ。CI・コードレビュー・ドキュメント生成の3ツールをアンカーに選定し、MVP前にPoCを完了。各ツールの実装と相互運用を、単独のバリデータ実装（CSF Validator）が自動検証する。
■ 採用の実証: アンカー3ツールの採用意向と実装計画を取得。採用ツール数と相互運用の実測値を最優先KPIとして公開し、参入障壁の実体を築く。
■ 差別化: 「規約＋参照実装＋RFC」の定型から一歩離れ、領域固有の運用課題（文脈の陳腐化・秘匿性）を規約の検証対象として組み込む。
■ 収益・持続性: オープン規約。スポンサー・採用ツールの商用版・コンサル。採用実績を根拠にした資金調達を想定。
■ v2からの変更点: 抽象的なエコシステム構想を、アンカー3ツールのPoC・バリデータ実装・KPIという実行と数字へ落とした。
```

**v4 改訂案（作成スキルの再作成指令を反映）**
```
■ プロジェクト名: STRAND（ストランド）— v4改訂版
■ 種別: CSF規約＋適合試験スイート＋ガバナンス＋redaction層
■ 概要: バリデータを正式な適合試験スイート（Conformance Suite）へ昇格。採用ツールの規約準拠を自動検証し、検証結果を公開する。採用を3ツールから拡大し、移行コスト・相互運用の実測値をデータとして蓄積。
■ ガバナンス: RFCプロセス・SemVer・ワーキンググループによる変更手続きを明文化。フォーマットの耐久性を制度的に担保。
■ 領域固有の中核: 文脈の秘匿（redaction）と陳腐化（stale context）の処理を、規約の必須仕様として中核に据え、汎用データ交換規約と差別化する。
■ 収益・持続性: オープン規約。適合認定を伴う商用サポート・コンサル。採用実績とガバナンスの成熟でエンタープライズ参入を図る。
■ v3からの変更点: バリデータを適合試験へ昇格し、ガバナンスとredactionという領域固有の中核を規約に組み込んだ。
```

**v5 改訂案（作成スキルの再作成指令を反映）**
```
■ プロジェクト名: STRAND（ストランド）— v5改訂版
■ 種別: CSF規約＋適合認定制度＋財団運営によるエコシステム基盤
■ 概要: 適合試験を第三者が運営する認定制度（Certified CSF）へ発展。規約準拠の検証を自己定義の域から離し、中立的な検証主体が採用ツールを認定する。認定ツールの一覧と相互運用の実測値を公開データとして整備。
■ ガバナンス: 運営を単独プロジェクトから財団（非営利）へ移し、RFC・ワーキンググループ・資金の持続性を制度的に担保。redaction・陳腐化処理を規約の必須仕様として維持・拡張。
■ ネットワーク効果: 採用数・移行コスト・相互運用便益の実測データを蓄積し、採用が増えるほど離脱コストが上がる複利構造を実証する。
■ 収益・持続性: 財団スポンサー・認定制度の費用・商用サポート。規約はオープンのまま、検証と認定という仕組みをエコシステムの価値中心にする。
■ v4からの変更点: 検証を自己定義から第三者認定へ昇格し、運営を財団化。ネットワーク効果を実測データで裏付ける段階へ進めた。
```
