# Calibration Suite — 較正スイート

Wisdom Council Layer は10体の評価者エージェントをそれぞれ**3言語版**（en / ja / zh）で提供している。較正はその言語版について**2つの異なる問い**に答える。

1. **静的ドリフト** — 翻訳の過程で*数値*（重み・スコア帯・較正値）がずれていないか？
2. **挙動ドリフト** — LLMが*同じ数値*でも言語によって異なる厳格さでスコアを出さないか？

静的チェックは**実装済み・PASS**。ランタイムチェックは**セッション再起動待ち**（[§2](#2-ランタイム較正未実施) 参照）。

## 1. 静的較正ドリフトチェック（実装済み・PASS）

全30ファイル（10評価者 × 3言語）の数値的較正契約が言語間で完全一致することを検証する。これにより「翻訳中に数値が変わった」系のドリフト（例: 重みが `0.35` の代わりに `0.30` に変わっている）を排除する。

### 検証対象

10評価者それぞれについて、en / ja / zh で:

| チェック | 抽出元 | 形式 |
|---------|--------|------|
| **次元重み** | `#### N. … — weight 0.35` 見出し行 | 小数4つ・順序保持 |
| **スコア帯** | Scoring Guidelines 節の `- 0-10:` … `- 91-100:` バレット | 範囲6つ |
| **較正表** | Calibration Reference 表の2列目 | `N-N` 範囲（注釈は無視） |

### 実行方法

```bash
python utils/check_calibration_drift.py        # 評価者ごとのPASS/FAILを人間可読で表示
python utils/check_calibration_drift.py --json # 機械可読（CI用）
```

終了コード `0` = PASS、`1` = FAIL。スクリプトは下記の落とし穴を防御しており、抽出が空でも黙ってPASSせずFAILとして報告する。

### 現状

**PASS — 2026-08-10。** 全10評価者 × 3チェックで en / ja / zh が完全一致。（スコア帯は10評価者すべて同一。重みと較正値は評価者ごとに固有だが言語間では一致。例: `business-value` → `15-30 / 40-60 / 60-80 / 80-95`、`anti-generic-filter` → `10-25 / 30-50 / 60-80 / 70-90`。）

**PASS が証明しないこと:** 同じ数値でも LLM が言語ごとに同じ厳格さで適用するとは限らない。それが挙動ドリフトであり、ランタイムチェックでのみ測定できる。

## 2. ランタイム較正（未実施）

> **実行ランブック**: 再起動後の手順をコピペで進められる詳細版は [`references/runtime-calibration-runbook.md`](../runtime-calibration-runbook.md) にある。以下はその要約。

### なぜブロックされているのか

エージェント名は**セッション起動時**にレジストリへ読み込まれる。新規作成した `-ja` / `-zh` のsymlinkは再起動まで解決されず、同一セッション内では Agent tool が `Agent type 'originality-ja' not found` と報告する。

この状態でスキルを実行すると、SKILL.md のR3対策により**沈黙裡に無接尾辞（英語）へフォールバック**し、「3言語が一致」したように見えて実際は「3回とも英語で評価」という無意味な結果になる。再起動後に実行することでこれを回避する。

### 手順（再起動後）

1. 接尾辞付きエージェントが登録されていることを確認（例: `ls ~/.claude/agents/originality-ja.md`）。
2. **同一内容を3言語に翻訳したサンプル**を用意する — テキスト自体の言語が評価に影響するため、言語間比較には「同じ意味の文章」が必須。
3. 言語ごとにスキルを実行:
   ```
   Skill: wisdom-council
   Args: {"content": "<3言語版テキスト>", "content_type": "text", "domain": "creative", "lang": "en|ja|zh"}
   ```
4. 出力JSONから `primary_score` / `dimension_scores.*.score` を収集し、言語間の分布（中央値・平均・分散）を `utils/compare_reports.py` または集計スクリプトで比較。
5. **判定**（`references/scoring-strictness.md` に基づく）: 厳格さのドクトリンが再現されているか — 中央値≈30、凡庸は50未満。言語別の系統的バイアス（英語が高め/低め等）が見えたら、英語プロンプトを正規ソースとして修正し、ja / zh を再翻訳する。

## 3. 落とし穴（静的チェック構築中の知見）

これらは「10/10 不一致」という結果がすべて**スクリプト側のバグ**だったことから得た知見。内容のドリフトはゼロだった。将来のチェッカーにも活かすこと。

1. **空リストの一致は「偽PASS」。** `[] == [] == []` は `True`。抽出が完全に失敗しても一致判定は通る。**対策**: 非空かつ一致の両方を要求し、抽出例を1つプリントして全滅を可視化する。
2. **`##+` 正規表現が `####` 見出しを吞む。** `r"##+ .*"` で節を探すと `#### 1. …` 次元見出しに続く "High score" 行がマッチし、節が途中で切れる。**対策**: 節分割は `^#{2,3}` のみで行い、`####` 行は親節の本文として保持する。
3. **較正値に括弧注釈が付く。** `| … | 75-95 (quality/marketability expected to be low) |` — `N-N` を `|` 境界に固定すると取りこぼす。**対策**: セル内の任意位置から `N-N` を抽出する。
4. **CJK文字は `\w`。** `\b2-3\b` は `- 2-3段落` にマッチしない（数字直後がCJK `\w`）。英語 `- 2-3 paragraph` はスペースで切れる。**対策**: `\b` ではなく行頭/セル境界で判定する。
